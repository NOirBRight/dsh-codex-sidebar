# DSH Alpha4 client integration uses the split official services

DSH 0.1.2-alpha.4 removes `dsh-client-runtime` and assigns its responsibilities to explicit Session Controller, Workspace Controller, Client store, UI Renderer, UI Session, and API Remote modules. The Sidebar Client therefore takes `Context` from Cordis, snapshot contracts from the Client store, and runtime services only through the official injected faces. One plugin-owned Conversation Projection Adapter reads the official `chat` target: canonical `order`/`nodes` and each node's location are authoritative for transcript consumers, while the legacy compatibility slice is a capability-detected fallback contained inside that Adapter; if neither shape is available, affected transcript projections return unavailable data without reading Session lifecycle state as message history. The plugin manifest loads the official Client modules that provide those faces; DSH packages remain peers rather than runtime dependencies, so the plugin cannot hoist a second Host singleton into a profile. Version 0.5.0 supports only the exact official 0.1.2-alpha.4 release and does not claim compatibility with later prerelease or final assemblies until their public Client contracts are revalidated. A dedicated Client compiler face checks `src/client` against a clean, built checkout of the exact official Alpha4 revision and emits the declaration advertised by the `./client` export. The checkout is selected through `DSH_ALPHA4_CHECKOUT`, validated for repository, revision, cleanliness, and required declarations, then linked only through a gitignored development path; no DSH source or artifact enters the package. The managed Browser remains one plugin-owned module behind these official services; it contains no DSH-version branches and requires no Core patch. Generated `lib` files are refreshed only by the release build.
