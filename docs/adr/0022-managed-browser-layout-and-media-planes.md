# Managed Browser has one layout authority and separate control and media planes

The Host owns one revisioned `BrowserLayout` for each Browser Tab. It commits the selected mode, CSS viewport, and media generation only after Chromium accepts the viewport. The client keeps its local container size, the committed CSS viewport, and encoded media dimensions as separate values. Fixed presets do not consume container measurements; fit measurements settle before one proposal. A media frame, Canvas backing size, WebRTC video size, or `Page.screencastFrame` device metadata cannot resize Chromium or replace the committed viewport.

The authenticated Browser WebSocket is the always-available control plane. It carries protocol negotiation, layout proposals and commits, revisioned input, page state, WebRTC signaling, route state, and bounded JPEG fallback. A matching revision is required for input, and a matching revision plus media generation is required for fallback acknowledgements. The client retains the last good presentation across a layout change and switches presentation and coordinate mapping together after media for the new generation is ready.

Direct media uses a Browser-owned, video-only WebRTC peer when STUN-only ICE succeeds. It is independent from Mobile Pairing and never requests camera, microphone, or audio. The Host encoder is isolated from the target Page and receives pixels only. Its configurable JPEG capture profile always uses the Host-committed viewport and is independent from the control socket's fallback profile, so an Origin-less Mobile connection keeps the 96 KiB tunnel ceiling without imposing that ceiling on encoder input. Negotiation failure selects JPEG fallback without interrupting control. Retry is bounded by cooldown and an explicit lifecycle signal; TURN and continuous retry are rejected. Each direction accepts at most 64 ICE candidates per attempt, including the end marker; pre-description client candidates cannot grow beyond that limit. A hidden document or offscreen Browser surface retains its control connection for the Host-advertised grace period. Visibility recovery cancels teardown; grace expiry closes the control connection and releases the peer and encoder while preserving the target Page. Authoritative `session/disposed` releases that session's control sockets, managed Pages, and cached file port. Plugin shutdown gives sockets and started work one configured deadline, then terminates unresponsive sockets and stops retaining unfinished task bookkeeping.

JPEG fallback is an interaction-first route for constrained Mobile tunnels. Every connection retains at most one capture, one unacknowledged frame, and one latest dirty request. Its configured frame interval is a hard capture-rate ceiling. Interaction, navigation, refresh, and layout commits replenish a bounded passive-frame budget, so the latest resulting repaint is delivered but animation alone eventually stops producing fallback frames. Encoding may lower JPEG quality or encoded resolution to meet the configured byte ceiling, but it cannot change the committed CSS viewport. Exact Browser evidence remains a separate capture from the target Page.

The stream exposes cumulative diagnostics for layout proposals and commits, stale input and capture drops, fallback bytes and recaptures, and media attempts, failures, and route reasons. These counters do not alter the live resource counts used to prove socket, timer, capture, unacknowledged-frame, and peer teardown.

The older model, where screencast device dimensions selected screenshot and client viewport dimensions, was rejected because CDP reports device screen dimensions rather than the controlled Page layout viewport. WebRTC without the revisioned layout model was also rejected because replacing the carrier would preserve the geometry feedback loop.
