# Managed Browser has one layout authority and separate control and media planes

The Host owns one revisioned `BrowserLayout` for each Browser Tab. It commits the selected mode, CSS viewport, and media generation only after Chromium accepts the viewport. The client keeps its local container size, the committed CSS viewport, and encoded media dimensions as separate values. Selecting a fixed preset produces exactly one `layout-propose` on the owning control WebSocket; persisted UI state, stream-ticket issuance, and the Browser adapter do not commit layouts out of band. Fixed presets do not consume container measurements; fit measurements settle before one proposal. A media frame, Canvas backing size, WebRTC video size, or `Page.screencastFrame` device metadata cannot resize Chromium or replace the committed viewport.

The authenticated Browser WebSocket is the always-available control plane. It carries protocol negotiation, layout proposals and commits, revisioned input, page state, WebRTC signaling, route state, and bounded JPEG fallback. A matching revision is required for input, and a matching revision plus media generation is required for fallback acknowledgements. The client retains the last good presentation across a layout change and switches presentation and coordinate mapping together after media for the new generation is ready.

Direct media uses a Browser-owned, video-only WebRTC peer when STUN-only ICE succeeds. It is independent from Mobile Pairing and never requests camera, microphone, or audio. The Host encoder is isolated from the target Page and receives pixels only. Its configurable JPEG capture profile always uses the Host-committed viewport and is independent from the control socket's fallback profile, so an Origin-less Mobile connection keeps the 96 KiB tunnel ceiling without imposing that ceiling on encoder input. Negotiation failure selects JPEG fallback without interrupting control. Retry is bounded by cooldown and an explicit lifecycle signal; TURN and continuous retry are rejected. Each direction accepts at most 64 ICE candidates per attempt, including the end marker; pre-description client candidates cannot grow beyond that limit. A Browser surface remains mounted but hidden and inert when another tool Tab is active. The client reports that visibility change with the exact owner, layout revision, and media generation while the hidden grace keeps its control connection alive. Visibility recovery cancels teardown; grace expiry closes the control connection and releases the peer and encoder while preserving the target Page. Authoritative `session/disposed` releases that session's control sockets, managed Pages, and cached file port. Plugin shutdown gives sockets and started work one configured deadline, then terminates unresponsive sockets and stops retaining unfinished task bookkeeping.

The client exposes direct video, low-bandwidth fallback, reconnecting, and unavailable as distinct presentation states. It does not claim direct video until the exact current generation has decoded its first frame. Pending and inactive video slots remain `display:none`; the active video and fallback Canvas use the same centered `contain` geometry. Any local condition that prevents presentation declines that owner, layout revision, and media generation; a stale receiver cannot decline a replacement generation.

JPEG fallback is an interaction-first route for constrained Mobile tunnels. Every connection retains at most one capture, one unacknowledged frame, and one latest dirty request. Its configured frame interval is a hard capture-rate ceiling. Interaction, navigation, refresh, and layout commits replenish a bounded passive-frame budget, so the latest resulting repaint is delivered but animation alone eventually stops producing fallback frames. Encoding may lower JPEG quality or encoded resolution to meet the configured byte ceiling, but it cannot change the committed CSS viewport. Exact Browser evidence remains a separate capture from the target Page.

The stream exposes fixed-memory diagnostics without page URLs or content. They include layout revision/generation gauges; capture, fallback encode/send, encoder Canvas paint, and fallback acknowledgement latency aggregates; encoded bytes and route-budget drops; media outcomes; and current peer, encoder Page, capture, socket, and timer gauges. These diagnostics do not alter the existing `resources()` fields used to prove socket, timer, capture, unacknowledged-frame, and peer teardown. At media capacity, the oldest hidden owner is released by exact identity before any negotiating fallback owner. A visible connected owner is not a capacity victim, admission falls back when none is safe to release, and `maxMediaPeers` cannot exceed the encoder Page budget.

The Browser surface publishes one non-sensitive `data-browser-presentation` JSON value for local diagnostics. It records connection state, committed and presented layout identities, viewport, encoded and surface sizes, media route, the single active Canvas or video slot, and active video intrinsic size, but never URL, title, page content, or signaling data. Each write replaces one complete state after its DOM presenter switch; direct video is published only when that video and the committed layout share the presented generation. Disconnect replaces layout and presenter fields with explicit null or none values. The attribute is observational: neither layout proposals nor presentation geometry read it.

The older model, where screencast device dimensions selected screenshot and client viewport dimensions, was rejected because CDP reports device screen dimensions rather than the controlled Page layout viewport. WebRTC without the revisioned layout model was also rejected because replacing the carrier would preserve the geometry feedback loop.
