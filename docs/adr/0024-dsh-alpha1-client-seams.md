# DSH Alpha1 client integration uses the split official services

DSH 0.1.2-alpha.1 removes `dsh-client-runtime` and assigns its responsibilities to explicit Session Controller, Workspace Controller, Client store, UI Session, and API Remote modules. The Sidebar Client therefore takes `Context` from Cordis, snapshot contracts from the Client store, and runtime services only through the official injected faces. The plugin manifest loads the official Client modules that provide those faces; DSH packages remain peers plus exact development fixtures rather than runtime dependencies, so the plugin cannot hoist a second Host singleton into a profile. Version 0.5.0 supports the 0.1.2 release lane and does not claim compatibility with RC assemblies that lack these modules. A dedicated Client compiler face checks `src/client` against that assembly and emits the declaration advertised by the `./client` export. The managed Browser remains one plugin-owned module behind these official services; it contains no DSH-version branches and requires no Core patch. Generated `lib` files are refreshed only by the release build.
